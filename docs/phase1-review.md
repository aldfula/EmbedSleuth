# Phase 1 독립 검토

검토일: 2026-11-18. 사용자 요청에 따라 세 에이전트가 계약·정책, SSH·원격 검사, 증거 저장을 나눠 검토하고 주 에이전트가 설계와 통합 경로를 확인했다.

## 판단

**Phase 1은 설계에 맞는 기반으로 진행됐다.** 기존 113개 테스트가 통과했고, AI와 결정적 실행의 분리, 엄격한 요청 계약, 검토 프로필, 미확인 선행 조건 차단, 증거 참조 검증이 구현됐다. Phase 1은 순수 판정 단계이므로 SSH·I2C 실행과 실제 Pi 지원을 입증하지는 않는다.

다음 두 보완을 반영한 뒤 Phase 2를 진행했다.

| 발견 | 영향 | 수정·검증 |
|---|---|---|
| frozen 모델 내부의 observations 딕셔너리는 공유될 수 있음 | 외부 객체 변경이 증거에 전파될 가능성 | 증거·보고서 경계에서 JSON 직렬화와 재검증으로 복사; 변경·잘못된 중첩 값 회귀 시험 |
| 한계 목록에 공백 문자열을 허용 | 형식상 한계가 있지만 내용은 없는 보고서 가능 | 공백 제거·비어 있지 않은 문장·길이 제한 적용 |

`tests/test_phase1_review.py`에 13개 회귀 시험을 추가했다. 계약은 여전히 반환 객체 내부의 모든 딕셔너리를 재귀적으로 불변화하지 않는다. Phase 2에서는 저장된 JSON을 권위 있는 스냅샷으로 사용하고 각 응답을 분리해 외부 변경이 저장 증거를 바꾸지 않도록 했다.

## Phase 2로 이어진 검토

독립 검토에서 발견한 다음 통합 문제도 수정·회귀 검증했다.

- SSH 공개 키 지문까지 비밀로 마스킹되던 문제: 정확한 공개 SHA-256 형식만 보존한다.
- 시스템 조사에 들어 있는 식별값처럼 보이는 필드로 완료를 판단하던 문제: 실제 식별 도구 실행과 저장된 증거를 결합한다.
- 성공 증거가 취소 보고서를 complete로 덮던 문제: interrupted를 유지한다.
- 잘못된 식별 응답 후 새 operation_id로 재시도할 수 있던 문제: 환경을 무효화하고 실행을 차단한다.
- 결과 저장과 완료 감사 기록 사이의 중단 문제: 결과와 중복 방지 캐시를 먼저 저장하고, 복구 시 재실행 없이 격리한다.
- 복구 후 과거 complete 보고서가 남는 문제: 조회 시 복구 상태를 반영해 재생성한다.

최종 테스트 수와 미검증 범위는 [구현 계획](implementation-plan.md#phase-2-검증)을 따른다. 코드 검토와 모의 시험 통과를 실물 안전성이나 MVP 전체 완료로 해석하지 않는다.
