# EmbedSleuth 요구사항

기준일: 2026-11-24. 요구사항의 구현·검증 상태는 [구현 계획](implementation-plan.md)에서 관리한다.

## 제품 범위

기존 AI CLI에서 목표를 요청하고 스킬·훅·MCP를 결합해 데이터시트 기반 부품 호환성과 실제 임베디드 장치를 진단한다. 첫 MVP는 SSH로 Raspberry Pi 3–MPU6050의 I2C 연결·인식을 읽기 전용으로 진단한다. 변경 실행은 후속 범위다.

AI·MCP·자료 관리는 PC, 하드웨어 접근은 Pi의 단기 프로세스에서 수행한다. LLM API를 직접 호출하지 않으며 기존 호스트의 모델 정책을 따른다.

Phase 1은 입력·결과·증거 계약, 프로필, 읽기 선행 조건의 **순수 판정**을 검증한다. Phase 2는 대상 레지스트리·코어 상태·예산·저장·SSH·원격 검사기를 오프라인 시험한다. 실제 SSH/Pi 인수와 MCP 강제 경로는 각각 Phase 6과 Phase 3에서 검증한다. 데이터 모델만으로 실물 안전성을 검증했다고 주장하지 않는다.

## Phase 3 세부 인수

- 로컬 STDIO만 제공하며 기존 아홉 입력 스키마를 그대로 게시한다. 모든 도구 호출은 엄격한 검증과 기존 코어를 통과한다. 임의 셸·경로·대상 등록 도구를 추가하지 않는다.
- 접속 설정은 신뢰된 시작 인자와 소유자 관리 파일에서만 읽는다. 빈 대상 목록도 프로필 조회·오프라인 연결 확인에 사용할 수 있으며 시작만으로 SSH에 접속하지 않는다.
- structuredContent와 텍스트 JSON의 일치, 공통 outputSchema, 실행 오류의 isError=true를 검증한다. 비교 불일치와 검사 실행 실패를 구분한다.
- 스키마·자원 제한·세션·저장 오류는 고정된 안전한 메시지와 코드로 응답한다. 원래 예외나 유효하지 않은 입력을 로그·응답에 반사하지 않는다.
- 실행 용량 초과 요청을 대기시키지 않는다. 취소 도구의 별도 용량을 확보하고 MCP 요청 취소를 코어에 전달한다.
- 입력이 계속 열려 있거나 호스트가 출력을 읽지 않아도 SIGINT·SIGTERM으로 서버가 종료돼야 한다. EOF·출력 단절·종료 신호·MCP 취소 시 작업자 기록을 마치고 저장소를 닫는다. 불명확한 원격 완료를 성공으로 추정하지 않는다.
- 실제 STDIO 자식 프로세스, SDK 자동 협상과 legacy 협상, 로그 stdout 분리, 강제 종료 후 복구를 네트워크·Pi 없이 시험한다. 전체 AI 호스트의 승인·도구 선택·스킬·훅 동작은 이후 별도 인수한다.

## Phase 2 세부 인수와 운영 조건

- PC에 등록한 연결만 사용하며 호스트 키를 자동 수락하지 않는다. 동일 정규화 호스트·포트의 중복 대상 ID를 거부하며 물리 장치당 안정된 ID와 공유 저장소를 운영 조건으로 요구한다. 실행 중 등록·신뢰 파일 변경은 선행 조건을 무효화한다.
- 기본 예상 버스 1은 등록 값이며 검사로 존재·접근·어댑터 기능을 확인한다. 모델이 다른 버스를 지시할 수 없다.
- Pi 3 모델, 부트 ID·SSH 키·어댑터 지문, 30초 이내 환경 증거를 결합한다. 읽기 직전 원격에서도 필수 조건을 재확인한다.
- 다른 사용자 공간 I2C 작업의 부재는 자동 입증할 수 없다. 신뢰된 운영자가 이를 배제했다고 등록한 경우에만 읽기를 허용한다. 기본값은 미확인으로 차단한다.
- 고정 결합 읽기만 사용한다. 오류·시간 초과·잘림·잘못된 응답 후 새 operation_id로 같은 실행을 재시도하지 않는다.
- 원격 의도 기록 → 결과와 중복 방지 캐시 저장 → 완료 기록의 순서가 저장 실패 시험에서도 보장돼야 한다. 의도 저장 지연 후 예산·TTL·신선도가 만료됐다면 실제 원격 전송을 시작하지 않는다.
- 미완료 원격 작업은 영속 격리하고 새 실행·재시작으로 우회하지 않는다. 살아 있던 다른 서버가 작업자 중단을 놓치지 않도록 대상 잠금 아래 모든 동일 대상 실행을 복구한다. 이미 완료된 캐시는 원래 증거와 시각으로 조회할 수 있다.
- 취소는 실행 잠금과 독립적으로 기록한다. 진행 중 취소·원격 종료 불명확은 interrupted로 보고하며 종료를 추정하지 않는다.
- 설정 요약은 일부 I2C 지시문만 수집한다. include·조건·실행 중 Device Tree 전체 해석이나 전기적 검증을 주장하지 않는다.
- complete는 현재 부트·호스트 키·어댑터의 정해진 식별 검사 범위가 충족됐다는 뜻이다. 과거 환경의 성공 결과로 현재 환경의 범위를 대체하지 않는다. 하나의 예상 주소에서 일치하거나 모든 예상 주소에서 유효한 비교가 있어야 한다. 장치 전체 정상 판정과 다르다.

## 판정 의미

| 관측 | 허용 판정 | 금지할 과잉 결론 |
|---|---|---|
| 권한 거부·도구 없음 | 해당 검사 불가 | 센서 고장 |
| 장치 노드 없음 | 사용자 공간 I2C 접근 경로 미확인 | 확정된 배선 불량 |
| 드라이버 점유 | 원시 읽기 중단 | 실제 식별 응답 성공 |
| I2C 전송 실패 | 해당 조건의 통신 실패 | 센서 사망·단선 확정 |
| 식별값 일치 | 예상 프로필에 맞는 응답 | 정품·정확도·전체 배선 정상 |
| 필요한 전기 정보 누락 | unknown/conditional | 전기적 호환 확정 |

status는 실행 성공 여부, assessment는 검사 조건 판정이다. 오류·출력 잘림·부분 결과로 pass를 확정하지 않는다. 알려진 증거 ID가 있다고 해서 AI 주장의 의미가 자동 검증되는 것은 아니다.

## 문서 검토 근거

검토일 2026-11-17. 제조사 작성 PDF의 공개 배포 사본을 내려받아 문서 번호·개정·아래 항목을 확인했다. 제조사 기존 링크의 오류 때문에 배포 사본을 사용했고 원래 URL과 실제 검색·다운로드 URL을 프로필에 별도로 기록했다. 해시는 사본 식별용이며 문서의 암호학적 진품 인증은 아니다.

|---|---|---|
| RM-MPU-6000A-00 Rev 4.2 | §4.32 p45 | WHO_AM_I 0x75, 기대값 0x68, AD0 미반영, read-only |
| PS-MPU-6000A-00 Rev 3.4 | §6.3 p14 | IC의 VDD 2.375–3.46V |
| 같은 문서 | §6.4 p15 | AD0에 따른 0x68/0x69, 최대 I2C 400kHz |
| 같은 문서 | §9.3 p35 | 레지스터 포인터 선택과 repeated START를 포함한 읽기 |

- [레지스터 맵 배포 사본](https://www.komputer.de/wordpress/wp-content/uploads/2023/06/MPU-6000.pdf): SHA-256 `7a628250765bbc4f5eae85fcadc40c8aa9770dba34a5c0fb54df91c537639ebd`
- [제품 사양서 배포 사본](https://cdn.sparkfun.com/assets/a/4/6/8/e/MPU_6050.pdf): SHA-256 `a4fdf69590b8cbab1cf0a5bcd359327b0ac022061fb233855aff2e191e7e3584`

전체 PDF는 저장소에 포함하지 않는다. 런타임은 다운로드하지 않으며 패키지의 검토된 값만 사용한다. 공급 전압 사실은 IC 범위이며 모듈 VCC 허용 범위나 GPIO 논리 호환을 뜻하지 않는다. VLOGIC·풀업·전원 순서 등 연결별 검토가 남아 있다.

## MVP 릴리스 기준

- 안전·부정 인자 시험 모두 통과.
- 지원 이미지·커널·아키텍처를 명시하고 실제 Pi에서 양쪽 주소를 검증.
- 훅 실패 시 코어 제한 유지, 중단·시간 초과 후 안전한 종료 검증.
- 모든 도구 관측이 실행 증거로 추적되며 부분 결과도 보고.
- 추가 peak RSS 합계 64MiB 목표와 시간·호출·출력 예산 실측.
- 모델·호스트·스킬 버전을 기록한 실제 에이전트 평가 통과.
- 센서 식별과 전기적 호환성·실물 정상 보장을 구분해 설명.

실물 시험 전에는 Raspberry Pi 3나 특정 OS를 지원 검증 완료로 표시하지 않는다. 전기 위험 시험은 과전압·단락 대신 모의 입력으로 수행하고 시험 환경 변경은 별도 승인된 준비 작업으로 분리한다.
