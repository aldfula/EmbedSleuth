# 구현 계획과 검증 기록

기준일: 2026-11-25. 사용자 승인에 따라 확정 아키텍처로 개발을 시작했다. 각 Phase의 결과와 아직 검증하지 않은 범위를 분리해 보고한다.

현재 Phase 6의 합의된 MVP 인수를 마쳤다. 엄격한 전체 추가 RSS·0x69 실물·일반 라우팅/OS 확대 등은 확장 범위로 기록한다. 단계가 통과할 때마다 이 표와 검증 기록을 갱신한다. 실물 접속은 사용자가 지정한 범위에서 수행하고 시스템 변경은 별도 승인을 요구한다.

## Phase 1 구현

- src 레이아웃의 설치 가능한 Python 패키지와 개발 의존성 정의.
- contracts.py: JSON 경계의 엄격한 요청, 실행 결과, 증거, 발견 사항, AI 원인 후보, 보고서.
- tools.py: 아홉 개 MVP 도구의 입력 스키마와 검증. 도구 실행·MCP 서버는 포함하지 않음.
- profiles.py 및 data/profiles/mpu6050.json: 명시적 ID 로딩, 검토된 IC 사실, 출처·개정·해시, 식별 비교.
- policy.py: 미확인 선행 조건을 차단하는 읽기 판정. 실제 관측과 권한 부여가 아님.
- pytest: 정상 주소 양쪽, 불일치·잘못된 타입·임의 실행 인자·미확인 정책·보고서 출처 경계 검증.
- README·아키텍처·요구사항·이 문서를 현재 기준 문서로 정리. design.md는 이전 논의 기록으로 보존.

정책 컨텍스트는 이후 코어가 실제 관측에서 생성한다. 모델 인자의 driver_bound·preconditions_fresh·approved 등은 거부한다. Phase 1의 정책 단위 시험은 훅·네트워크와 독립적이며 하드웨어 접근을 실행하지 않는다.

## Phase 1 검증

검증 환경: Linux x86_64, Python 3.12.14. Pydantic·pytest와 전이 의존성은 constraints-dev.txt에 고정한 검증 버전을 기록한다. 프로젝트의 최소 개발 대상은 Python 3.11이지만 이 버전의 실행 시험은 아직 수행하지 않았다.

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -I -m pytest -q -W error
```

결과: **113 passed in 0.11s**, 경고를 오류로 처리한 실행에서도 통과했다. 외부 ROS 패키지·pytest 플러그인이 처음 실행에 개입했으므로 최종 검증은 Python -I와 자동 플러그인 로드 비활성화로 격리했다. 시스템 ROS 패키지를 변경하지 않았다.

| 검사 | 결과 |
|---|---|
| pytest | 113개 통과, 경고 없음 |
| editable 설치 | pyproject.toml 기준 설치 성공 |
| wheel 빌드·임시 디렉터리 설치 | 성공; 저장소 밖 설치본에서 프로필과 아홉 도구 스키마 로딩 확인 |
| .venv/bin/python -I -m pip check | No broken requirements found |
| compileall | src·tests 구문 검사 통과 |
| 문서 검증 | README·docs의 로컬 링크와 코드 블록 닫힘 확인 |
| 원문 검증 | 내려받은 두 PDF의 SHA-256이 프로필 기록과 일치 |

주요 회귀 검증: 주소가 0x69여도 기대 식별값은 0x68, bool을 1바이트 길이·주소로 허용하지 않음, 미확인 권한·점유·상태에서 읽기 차단, 부분·오류 결과의 pass 차단, 실패한 증거만으로 성공 발견 사항 생성 차단, 다른 실행·대상·미등록 증거 참조 차단.

문서 근거는 제조사 원본 링크 접근 오류를 우회해 공개 배포된 동일 문서 번호·개정의 제조사 작성 사본으로 검토했다. 로컬에서 바이트 해시와 필요한 절을 확인했다. 전체 PDF를 저장소에 포함하거나 테스트 때 재다운로드하지 않는다.

검증하지 않은 범위: 실제 SSH·I2C, Pi 메모리·시간, 호스트의 MCP·스킬·훅 동작, 전기적 모듈 호환성, 모델의 추론 품질. 이 범위는 Phase 2–6 완료와 구분한다.

## Phase 1 재검토

2026-11-18에 독립 검토 에이전트와 실행·저장 담당 에이전트가 설계를 확인했다. Phase 1은 후속 실행 계층의 기반으로 적합하다고 판단했다. 내부 딕셔너리 공유와 공백 한계 문장 허용을 보완하고 13개 회귀 시험을 추가했다. [검토 기록](phase1-review.md)에 발견·수정·한계를 기록한다.

## Phase 2 구현

| 파일 | 구현 내용 |
|---|---|
| targets.py | 신뢰된 로컬 대상 등록, 절대 SSH 경로, 중복 ID 거부 |
| transport.py | Paramiko RejectPolicy·지정 신뢰 파일, 고정 명령과 stdin JSON, 공개 키 지문, 제한된 출력, spawn 감독 프로세스의 전체 기한·취소 |
| remote_probe.py | Pi 표준 라이브러리 검사기, 보드·OS·부트·I2C 환경, 설정 요약, 고정 i2ctransfer 식별 읽기와 제한된 자식 수명 |
| storage.py | 소유자 전용 저장소, no-follow·소유권·하드 링크 검사, 원자 교체·fsync, JSONL 감사, 실행·대상 잠금, 독립 취소 표시, 중단 복구·영속 격리 |
| core.py | 아홉 도구의 Python 코어, 세션·30초 신선도·부트/키/어댑터 결합·예산, 식별 캐시, 규칙 발견, 부분·중단 보고서 |

핵심 실행 순서는 아래와 같다.

1. 로컬 등록에서 SSH 연결과 예상 하드웨어를 결정하고 start_diagnosis로 실행을 만든다.
2. inspect_target에서 호스트 키·부트·보드 관측을 수집하고 inspect_i2c_environment로 등록 버스를 조사한다.
3. 순수 정책이 관측과 신뢰된 운영 선언을 모두 확인한 경우에만 식별 도구를 실행한다. Pi에서도 읽기 직전 필수 조건을 재확인한다.
4. 원격 호출 전 의도 기록을 저장한다. 결과·증거·식별 캐시를 먼저 저장하고 완료 감사 기록을 닫는다.
5. 저장 실패·취소·단절로 완료가 모호하면 재실행하지 않고 격리한다. 보고서 조회는 복구된 상태를 반영한다.

전체 I2C 스캔·sudo·설치·권한/설정 변경·리셋 도구는 추가하지 않았다. 모델·MCP 서버·PC 의존성은 Pi에 설치하지 않는다. Python 코어 사용 예와 환경 조건은 [Phase 2 사용 문서](phase2-usage.md)에 있다.

PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -I -m pytest -q -W error

### 남은 한계와 다음 단계

아래는 2026-11-18 Phase 2 완료 당시의 경계다. 이후 초기 실물 결과와 Phase 3 결과는 뒤의 기록을 따른다.

- 실제 SSH·Pi 3 I2C, 지원 OS·커널·32/64비트, peak RSS 64MiB 목표와 원격 프로세스 종료는 **미검증**이다.
- 다른 I2C 프로그램 배제는 운영자의 로컬 선언이다. EmbedSleuth 잠금이 장치 전체를 독점하지는 않는다.
- 부트 설정은 일부 지시문 요약이다. include·조건·Device Tree 전체 해석이나 전기 호환성 판정은 없다.
- 도구 기한에는 PC 감독 프로세스의 제한된 종료 대기 최대 0.2초와 OS 스케줄링 지연이 추가될 수 있다. 원격 커널 I/O 종료는 추정하지 않는다.
- 활성 예산 120초는 실행 생성부터의 경과 시간이며 모델 대기 시간도 포함한다. 실제 호스트 사용성을 보고 Phase 3–4에서 조정 여부를 검토한다.
- 파일 저장소는 Linux 전용이다. 보존·회전·격리 해제·운영 복구 UI는 아직 제공하지 않는다. 복구 순회 비용은 전체 실행 수에 비례한다. 물리 장치당 안정된 ID와 공유 저장소를 사용하며 DNS/IP 별칭·서로 다른 저장소의 동일 장치 여부는 자동 판별하지 않는다.
- MCP 서버·실제 스킬·훅과 전체 에이전트 평가가 아직 남아 있으므로 MVP 전체 완료는 아니다.

Phase 3에서는 아홉 도구를 공식 MCP SDK의 STDIO 어댑터에 연결한다. 코어의 예외를 정제한 구조화 오류로 바꾸고, 동시 취소·stdout 분리·서버 종료·서비스 재시작을 통합 시험한다. 정책·세션·저장 로직을 MCP 어댑터에 중복 구현하지 않는다.

사용자가 지정한 Pi를 대상으로 passive 검증을 시작했다. 사용자 확인상 MPU6050은 아직 연결되지 않았다.

| Pi 메모리·원격 프로세스 종료 계측 | 미수행 |
| Pi 변경 | 사용자 승인 범위의 SSH 공개키 등록 완료; I2C 설정·장치 접근 권한·패키지 변경 없음 |

실제 inspect_target과 inspect_i2c_environment를 기존 코어·기본 Paramiko 감독 전송·고정 원격 검사기로 실행했고 각각 약 0.96초·0.98초로 기록됐다. 이는 SSH와 검사기 실행을 포함한 도구 시간이며 Pi CPU 시간이나 메모리 측정값이 아니다. I2C 설정 요약에서 dtparam=i2c_arm=on을 관측했으나 전체 설정 해석을 주장하지 않는다. 실행 결과는 센서 식별을 생략한 partial 보고서로 PC의 소유자 전용 RunStore에 보존했다. 실제 접속 정보와 로컬 증거 파일은 저장소 문서에 포함하지 않는다. 첫 실물 접속에서 Paramiko의 인증 수단 부재 SSHException을 network_timeout으로 분류하는 문제를 발견해 authentication_failed로 수정했다. 원격 실행 시작 후 같은 오류 문자열이 발생한 경우에는 remote_state_unknown을 유지한다.

수정 검증: 전송 계층 42개, 전체 **377 passed in 16.01s**(경고 오류 처리). 이는 소프트웨어 회귀 결과다. 별도로 위 Pi 환경에서 SSH·표준 라이브러리 원격 검사·수동 I2C 어댑터 조회를 실물 확인했다. 센서 연결 후 WHO_AM_I·전송 오류·종료·메모리 검증은 남아 있으며, 연결 준비나 추가 설정 변경이 필요하면 구체적인 변경 범위를 별도 승인받는다.

- 정상 Pre는 중립 응답, 실패 Pre는 deny. 승인 허용·인자 변경 없음. Post는 원래 결과를 유지한 경고. Stop은 partial/interrupted 허용과 최대 1회 보완 요청. 일반 호출 64개 이후에도 종료·조회·취소용 16개 기록 여유를 둠.
- examples/codex-hooks.json과 경로 인용을 처리하는 생성기. 실제 운영 설정·호스트 신뢰는 자동 변경하지 않음.
- 개발용 Codex 확인기에 hooks/list 추가. 임시 설정에서 훅 3개의 검색·5초 timeout·untrusted·비관리 상태를 확인하고 미실행 여부를 검사.
- [운영 문서](hooks-usage.md)에 설정·사용자 검토·보존 정책·실패 동작·미검증 범위를 기록. 복잡한 에이전트 프레임워크·새 런타임 의존성·Pi 설치는 추가하지 않음.

[승인된 실물 변경 계획](hardware-fault-plan.md)에 따라 권한 임시 차단·dummy 점유·컨트롤러 임시 unbind의 대화형 시험 도구와 root 준비 가드를 작성했다. 준비 가드는 60초 lease·신호 정리·원래 모드/ACL·장치 동일성·생성한 클라이언트 확인·복구 메타데이터를 사용한다. 비밀번호를 수집하지 않고 본인 터미널에서 sudo를 사용한다. SIGKILL·전원 상실·커널에서 멈춘 I/O까지 복구가 보장된다고 주장하지 않는다. 이후 사용자 터미널 실행에서 실제 권한 거부·dummy 점유의 관측과 복구를 확인했다. 컨트롤러 비활성은 구형 sysfs 경로 가정으로 변경 전에 실패했다. i2c-dev 기반 경로를 사용하도록 수정했고 실제 Pi에서 읽기 전용 prepare가 changed=false로 통과했다. 통과한 두 사례는 반복하지 않고 마지막 한 건만 별도로 재실행했다. 실제 비활성 환경의 어댑터 부재와 복구 후 접근·미점유를 확인해 세 오류 시험 모두 통과했다. 각 기준·오류·복구 보고서는 partial이며 센서 읽기는 0회다. 제품 MCP에 변경 도구나 sudo를 추가하지 않았다.

### 잔여 인수 범위 조정과 실행 중 취소 — 2026-11-25

사용자 요청으로 0x69 실물 시험을 이번 인수에서 제외했다. 현재 0x68 WHO_AM_I 직접 읽기의 기존 pass는 유지한다. 생산 MCP의 실제 inspect_target 요청과 정확한 원격 검사기 관측을 병행한 뒤 취소해 interrupted·47.642ms 응답·닫힌 감사·pending=null을 확인했다. 8초 뒤 관측한 원격 프로세스 3개 종료를 확인했으며 영속 격리는 유지한다. 전체 자식 강제 종료를 주장하지 않는다. 취소 인수 검증기 15개를 포함해 전체 640개가 47.93초에 통과했다.

전체 메모리 사전 확인은 memory controller 비활성으로 unavailable이다. CONFIG_MEMCG=y, 부팅 시 cgroup_disable=memory, memory.peak 없음이 실제 관측이다. 부팅 파일 변경·재부팅·격리 해제는 하지 않았다. [검토 가능한 후속 계획](memory-cancellation-plan.md)에 변경 범위·복구·계측 지표 차이를 기록했다.

2026-11-26 사용자가 부트 파일 백업·계측 활성화·재부팅을 승인했다. 본인 터미널용 준비 실행기는 원본·백업 해시 결합, 기존 옵션 충돌 거부, fsync·원자 교체, 재부팅 후 기능 확인을 수행한다. 비밀번호 캡처·장치 검사·격리 초기화는 하지 않는다. 실제 Pi에서는 비특권 preflight만 확인했다. 임시 로컬 파일로 변경 전 경합·백업 충돌·쓰기 실패·단일 줄·소유자 터미널·재부팅 후 조건을 검사하는 23개 안전성 시험이 통과했다. 실제 root 실행은 사용자 터미널에서 진행한다.

관리자 준비 도구를 포함한 최신 전체 회귀는 663 passed in 46.46s(경고 오류 처리)이며, 문서 16개 링크·코드 블록과 diff 공백 검사를 통과했다. 사용자는 재부팅 후에도 0x68과 다른 I2C 프로그램 중지 조건을 유지하겠다고 현재 확인했다.


### 계측 활성화와 한정된 복구 준비 — 2026-11-26

사용자가 관리자 준비를 실제 완료했고 새 부트·backup/cmdline hash·memory controller와 memory.peak를 독립 대조했다. read-only cgroup 관측기의 실제 준비 점검도 통과했다. 취소 격리는 유지하며 장치 메모리 측정은 아직 수행하지 않았다.

닫힌 passive inspect_target 취소에만 적용하는 로컬 운영자 복구와 과금 메모리 인수 도구를 준비했다. 새 부트/SSH/등록·감사 결합을 확인하고 owner-only 복구 기록을 fsync한 뒤만 격리를 제거한다. 원래 interrupted/unknown 보고서는 보존한다. 코어가 새 복구 기록을 이해하도록 했으며 공개 MCP 변경 도구는 추가하지 않았다. 복구 적용은 별도 승인 대기이고 새 MCP 연결이 필요하다. 복구 20개·계측 판정 22개 추가를 포함한 최신 회귀는 705 passed in 48.42s다.


### 실제 계측 완료와 예전 호스트 호환성 정리

사용자 별도 승인 후 취소 한 건을 감사 가능한 방식으로 복구했다. 새 생산 MCP에서 passive와 0x68 식별 1회를 계측했고 과금 메모리 상한은 37.69MiB·37.97MiB였다. identity-match/pass·complete와 원래 등록 복원을 확인했다. 해당 과금 메모리는 엄격한 추가 RSS와 다른 지표로 기록한다.

마지막 구버전 호스트 조회기의 격리 재생성을 실제 관측해, 원래 감사 prefix와 동일한 무전송 복구 접미부만 허용하는 회귀 4개를 추가했다. 닫힌 보고서를 보존하고 유휴 구버전 MCP 한 개를 정상 종료한 뒤, 승인된 같은 취소 건의 복구와 새 생산 MCP 보고서 전용 검증을 마쳤다. 장치 검사는 반복하지 않았다. 최신 전체 시험은 709 passed in 48.88s이며 이전 대화의 MCP transport는 일반 사용 전 재연결이 필요하다.


## Phase 6 순차 인수 기준 정리 — 2026-11-26

메모리는 [별도 결정](memory-budget-decision.md)에 따라 진단 SSH·로그인 세션을 포함하는 커널 과금 메모리 최대 상한 64MiB를 필수 기준으로 사용한다. 기존 37.69/37.97MiB 실측의 저장 증거·부트를 재대조해 pass로 판정했다. 엄격한 전체 추가 RSS는 미측정 참고 항목으로 남긴다.

실제 모델·스킬·생산 MCP·신뢰된 훅의 한 턴 통합 검증은 [명시된 전송 범위](agent-evaluation-scope.md) 승인을 받아 진행한다. 별도 API 클라이언트·프레임워크·정책 우회는 추가하지 않는다. 가짜 3턴 결과와 새 실물 1턴은 구분하며, 별도 승인된 새 실물 passive 턴도 통과했다. 최종 회귀·새 wheel의 저장소 밖 설치·비공개 파일 제외 결과는 인수 기록의 최신 표를 따른다.


## Phase 6 인수 통과 — 2026-11-26

실제 gpt-6.1-sol / Codex CLI 0.172.0에서 명시 스킬·생산 MCP·신뢰된 Pre/Post/Stop·Pi passive 조사·최종 한국어 보고를 1턴으로 확인했다. 38.197초·MCP 6회·원격 2회·센서 전송 0회, run-e9257c79462e4d389e3b2e6ac94fbf8c의 partial 보고서·감사·영수증이 닫혔다. 모든 실제 주장·증거 ID·시각과 미확인 설명을 사람이 대조했다. 초기화 중단에는 모델/장치 실행이 없었고, 모델 턴은 승인된 1회만 사용했다.

평가기의 플러그인 제외·MCP 준비 이벤트 대기·비활성 빈 서버 판정 회귀 11개를 보강해 전체 **750 passed in 49.36s**(경고 오류 처리)다. 제품 런타임 코드·의존성·생산 MCP 아홉 도구는 이번 통합 검증에서 변경하지 않았다. 패키지·설치 검증은 앞선 새 wheel 결과를 유지한다. 지원 범위·미검증 확장은 [최신 인수 기록](phase6-acceptance.md)을 따른다. 공개 릴리스·커밋·푸시는 별도이며 수행하지 않았다.
