# 구현 계획과 검증 기록

기준일: 2026-11-17. 사용자 승인에 따라 확정 아키텍처로 개발을 시작했다. 각 Phase의 결과와 아직 검증하지 않은 범위를 분리해 보고한다.

Phase 1 결과를 확인할 수 있도록 이번 변경은 Phase 1의 완료 단위를 구현한다. Phase 2 이후는 위 순서로 진행하며 단계가 통과할 때마다 이 표와 검증 기록을 갱신한다. 실물 접속·설정 변경은 자동으로 수행하지 않는다.

## Phase 1 구현

- src 레이아웃의 설치 가능한 Python 패키지와 개발 의존성 정의.
- contracts.py: JSON 경계의 엄격한 요청, 실행 결과, 증거, 발견 사항, AI 원인 후보, 보고서.
- tools.py: 아홉 개 MVP 도구의 입력 스키마와 검증. 도구 실행·MCP 서버는 포함하지 않음.
- profiles.py 및 data/profiles/mpu6050.json: 명시적 ID 로딩, 검토된 IC 사실, 출처·개정·해시, 식별 비교.
- policy.py: 미확인 선행 조건을 차단하는 읽기 판정. 실제 관측과 권한 부여가 아님.
- pytest: 정상 주소 양쪽, 불일치·잘못된 타입·임의 실행 인자·미확인 정책·보고서 출처 경계 검증.
- README·아키텍처·요구사항·이 문서를 현재 기준 문서로 정리. design.md는 이전 논의 기록으로 보존.

정책 컨텍스트는 이후 코어가 실제 관측에서 생성한다. 모델 인자의 driver_bound·preconditions_fresh·approved 등은 거부한다. Phase 1의 정책 단위 시험은 훅·네트워크와 독립적이며 하드웨어 접근을 실행하지 않는다.

## Phase 1 검증

검증 환경: Linux x86_64, Python 3.12.14. Pydantic·pytest와 전이 의존성은 constraints-dev.txt에 고정한 검증 버전을 기록한다. 프로젝트의 최소 개발 대상은 Python 3.11이지만 이 버전의 실행 시험은 아직 수행하지 않았다.

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -I -m pytest -q -W error
```

결과: **113 passed in 0.11s**, 경고를 오류로 처리한 실행에서도 통과했다. 외부 ROS 패키지·pytest 플러그인이 처음 실행에 개입했으므로 최종 검증은 Python -I와 자동 플러그인 로드 비활성화로 격리했다. 시스템 ROS 패키지를 변경하지 않았다.

| 검사 | 결과 |
|---|---|
| pytest | 113개 통과, 경고 없음 |
| editable 설치 | pyproject.toml 기준 설치 성공 |
| wheel 빌드·임시 디렉터리 설치 | 성공; 저장소 밖 설치본에서 프로필과 아홉 도구 스키마 로딩 확인 |
| .venv/bin/python -I -m pip check | No broken requirements found |
| compileall | src·tests 구문 검사 통과 |
| 문서 검증 | README·docs의 로컬 링크와 코드 블록 닫힘 확인 |
| 원문 검증 | 내려받은 두 PDF의 SHA-256이 프로필 기록과 일치 |

주요 회귀 검증: 주소가 0x69여도 기대 식별값은 0x68, bool을 1바이트 길이·주소로 허용하지 않음, 미확인 권한·점유·상태에서 읽기 차단, 부분·오류 결과의 pass 차단, 실패한 증거만으로 성공 발견 사항 생성 차단, 다른 실행·대상·미등록 증거 참조 차단.

문서 근거는 제조사 원본 링크 접근 오류를 우회해 공개 배포된 동일 문서 번호·개정의 제조사 작성 사본으로 검토했다. 로컬에서 바이트 해시와 필요한 절을 확인했다. 전체 PDF를 저장소에 포함하거나 테스트 때 재다운로드하지 않는다.

검증하지 않은 범위: 실제 SSH·I2C, Pi 메모리·시간, 호스트의 MCP·스킬·훅 동작, 전기적 모듈 호환성, 모델의 추론 품질. 이 범위는 Phase 2–6 완료와 구분한다.

## Phase 2의 구체 작업 순서

1. 사용자 등록 대상과 예상 연결, 키 검증 정책을 정의하고 임의 대상 차단 시험 작성.
2. 주입 가능한 SSH 전송 인터페이스와 가짜 전송으로 연결·인증·출력·시간 초과 시험.
3. 고정 원격 검사기와 sysfs·설정 수집, i2ctransfer 제한 호출 구현.
4. 실행 상태·관측 신선도·버스 참조·operation_id 중복·예산 강제.
5. 정제된 증거의 추가 기록, 중간 보고서의 원자 저장, 중단·재시작 복구.
6. 오류를 센서 고장으로 오판하지 않는 규칙 보고서와 회귀 시험.

이후 Phase 3에서 실제 MCP 연결을 추가하고 Phase 4·5에서 호스트 사용 경험을 연결한다. Phase 6에서 시험 대상을 명시적으로 등록하고 안전한 실물 시험을 수행한다.
