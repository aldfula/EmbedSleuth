# 실제 모델 평가의 전송 범위

Phase 6의 모델 행동 시험은 사용 중인 Codex 호스트에 한 번의 테스트 요청을 전달한다. EmbedSleuth 제품에 LLM API 클라이언트나 별도 에이전트 루프를 추가하지 않는다.

## 이번에 요청하는 범위

- 목적지: 현재 로그인된 Codex의 OpenAI 모델 서비스. 확인된 provider는 openai, 기본 모델은 gpt-6.1-sol이며 별도의 base URL 재지정은 없다. 모델·인증·승인 정책을 바꾸지 않는다.
- 목적: 기존의 결정적 절차 재생과 구분해, 실제 모델의 스킬 선택·도구 선택·오류 중단·근거 보고를 확인한다.
- 횟수: 최초 인수는 최대 3개 요청. passive 명시 호출, 정상 주소 0x68, 드라이버 점유의 가짜 장치 사례를 사용한다. 한 요청의 모델 동작 제한은 최대 180초이며 재요청을 자동 반복하지 않는다.
- 전송할 프로젝트 자료: 공개 저장소의 diagnose-mpu6050 스킬 본문·참조·메타데이터, 아홉 MCP 입력 스키마·설명, 선택한 가짜 사례의 사용자 요청과 도구 관측·보고서. Codex의 일반 시스템 지시와 도구 실행 문맥도 호스트 동작에 따라 모델에 제공된다.
- 가짜 값: target_id=lab-pi, Pi 3 보드 문자열, 평가용 부트·어댑터·호스트 키 지문, I2C 선행 조건, 고정 식별 응답 또는 점유 오류, 합성 실행·증거 ID. 모의 서버는 ParamikoTransport를 사용하지 않는다.
- 제외: 실제 Pi 호스트·계정·SSH 경로·개인키·비밀번호·실물 증거 저장소·기존 대화. 인증 파일을 직접 읽거나 복사하지 않으며 별도 API 키를 생성하지 않는다. 기대 trace·채점 기준은 모델 입력에 넣지 않는다.

## 실행과 기록

개발용 [모델 시험기](../scripts/run_model_acceptance.py)는 저장소 밖의 임시 작업공간에 스킬만 복사하고, [평가 전용 MCP 서버](../evals/diagnose-mpu6050/server.py)에 가짜 fixture를 전달한다. 운영 프로젝트의 MCP·훅·대상 설정은 상속하지 않는다. 사용자 전역의 다른 MCP 서버는 해당 테스트 실행에서만 비활성화한다. 실제 모델은 ephemeral 문맥에서 한 턴을 실행하며 저장된 사용자 작업을 만들지 않는다.

평가기는 기본적으로 사용자 승인·질문 요청을 거부한다. 아래에 명시한 사용자 사전 승인 범위에서만 모의 읽기 호출에 일회성 승인 응답을 전달한다. 훅 신뢰를 우회하거나 승인 정책을 완화하지 않는다. 모델에게는 자격 증명 조회·SSH·네트워크·설정 변경을 금지하고 제공된 모의 MCP만 장치 검사에 사용하도록 지시한다. 문맥·결과·실제 도구 호출·코어의 가짜 전송 기록은 Git에서 제외한 .embedsleuth-local/evaluations 아래에 저장한다. 시간 초과·실패 시에도 수신한 이벤트를 보존한다.

모델 평가에는 현재 Codex 계정의 모델 이용 한도가 사용될 수 있다. 전송·보존·요금 정책은 해당 호스트와 계정 설정을 따른다. 이 문서나 오프라인 테스트 통과 자체가 외부 전송 승인은 아니다.

## 승인된 가짜 읽기 호출 범위

첫 실제 passive 평가에서는 Codex가 inspect_target 호출의 MCP 사용 승인을 요청했고, 기본 거부 정책에 따라 호출하지 않았다. 모델은 실행을 취소하고 interrupted로 보고했다. 이로써 승인 거부 시 중단 대응을 확인했으며 정상·점유 진단 자체는 검증되지 않았다.

남은 두 사례의 실제 도구 선택을 확인하려면 **별도 사용자 허용** 후 --approve-fixture-reads를 사용할 수 있다. 이 옵션은 identity-104·driver-bound의 모의 서버에만 적용된다. 해당 실행에서 만든 가짜 lab-pi run_id에 대해 inspect_target·inspect_i2c_environment·read_device_identity만 1회씩 최대 3개 승인 응답을 전달한다. 식별은 bus-1·주소 0x68로 제한한다. 코어 정책은 그대로 적용된다. 사용자의 승인 정책·MCP 영구 허용·실제 프로젝트·실물 Pi·훅 신뢰에는 적용하지 않는다. 범용 셸·기타 서버·취소/변경 도구·임의 실행 ID는 허용하지 않는다. 2026-11-25 사용자가 이 범위를 제시한 뒤 “ㄱㄱ”로 진행을 승인했다. 남은 두 모델 턴에서만 이 제한을 적용한다.

## 현재 상태

2026-11-25 첫 실제 모델 실행 시도가 자동 승인 검토에서 차단됐다. 구체적 payload와 목적지에 대한 사용자 승인이 명확하지 않다는 이유이며, 해당 시도에서 모델 요청과 평가 프로세스는 시작되지 않았다. 이후 사용자가 이 문서의 범위로 최대 3개 평가를 명시적으로 승인했다. 실행 전 실제 모델/provider를 다시 대조하고 이 범위에서만 진행한다. 한 평가 턴에는 도구 선택에 필요한 여러 모델 요청이 포함될 수 있다.

승인된 3턴을 모두 사용했다. passive의 승인 거부 후 중단, 정상 0x68의 단일 식별, 점유 시 읽기 생략을 검토했다. 각 사례와 남은 범위는 [인수 기록](phase6-acceptance.md)에 정리했다. 이 승인을 추가 모델 실행에 재사용하지 않는다.
