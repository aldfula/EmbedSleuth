# v0.2.0 로컬 후보 검증 — 2026-11-27

구현과 오프라인·설치 검증을 완료했다. 실제 Pi의 새 센서 기능·메모리·모델 행동 인수와 공개 배포는 아직 하지 않았다. PyPI의 현재 버전은 0.1.0이다. 아래 결과를 v0.1.0의 실물 인수와 합쳐 새 기능 전체가 실물 검증됐다고 해석하지 않는다.

## 자동 회귀

전체 회귀 **885 passed in 74.62s**, 경고 오류 처리. 실물 인수 클라이언트를 추가한 뒤의 결과다. 이후 false인 로컬 등록 선언을 현재 확인으로 덮어쓸 수 없게 하는 별도 조건을 보강했고, 센서 인수·게시 정책 묶음 **19 passed in 2.35s**를 확인했다. 현재 수집 목록은 886개다. 전체 회귀와 마지막 보호 조건의 집중 검증을 구분한다.

새 테스트는 기존 설정·다른 MCP/훅·README 보존, 반복 적용과 dry-run, malformed/중복 형식·링크·수정 스킬 거부, 실패 rollback, 새 외부 등록과 v0.1.0 원본 이전을 포함한다. 센서에서는 signed 변환과 16가지 범위 조합, 절전/활성, 지원하지 않는 설정, SLEEP 외 클록 비트 보존, 승인 없음/만료/변조/소진, durable intent 이후 만료, 오류·정상 복원·불확실한 IO·복원 실패·타인 설정 변화, 중복/재시작 캐시와 격리를 확인한다.

실제 MCP 런타임과 Pre/Post/Stop을 묶어 계획·로컬 승인·샘플·보고서를 시험했다. 외부 작업이 없는 sampling_planned 상태의 턴 종료는 허용하고, 미완료 원격 작업은 대기 예외로 숨기지 않는다. 로컬 승인 저장소 열기는 다른 실행을 자동 복구하지 않는다. 파이프 승인은 거부한다. 스킬 quick_validate도 통과했다. 이 시험은 실제 LLM의 라우팅이나 자연어 보고 품질을 평가하지 않는다.

`scripts/run_sampling_acceptance.py`는 운영자 본인 TTY에서 새로운 생산 STDIO MCP의 두 센서 도구를 확인하고, 현재 주소/충돌 배제 확인·식별·계획·생산 로컬 승인 명령·환경 갱신·수집·최종 보고서 조회를 한 번 수행한다. 승인을 생성하거나 I2C를 직접 조작하는 대체 경로는 없다. 가짜 장치 7개 조건에서 정상·거절·승인 누락·기한 경과·이전 서버 거절·비TTY·false 등록 선언을 확인했다. 이 클라이언트로 실제 Pi 검사를 실행하지는 않았다.

제한 환경에서는 MCP 로컬 통신 검사가 정지해 해당 실행을 중단했고, 이후 로컬 소켓/자식 프로세스를 허용한 환경에서 180초 상한으로 전체 검증했다. 실제 Pi·외부 모델·운영 설정을 사용하지 않았다.

## 빌드와 설치

wheel과 sdist를 만들고 `twine check --strict`를 통과했다. wheel의 코드/리소스 25개와 sdist의 같은 파일을 현재 소스와 바이트 단위로 비교했다. 메타데이터 이름·버전·UTF-8 README를 확인했고 경로 이탈·링크·비공개 설정 포함이 없음을 검사했다. README 문서 링크는 PyPI에서도 사용할 절대 GitHub 링크로 바꿨다.

로컬 후보는 `dist/v0.2.0-candidate`에 wheel·sdist·SHA256SUMS·VERIFICATION.json으로 보관한다. 커밋/태그로 고정된 공개 릴리스가 아니므로 게시 전 최종 소스 상태와 검증을 다시 결합해야 한다.

Linux/Python 3.12.14/pipx 1.19.1의 pip 백엔드에서 다음 인수를 통과했다.

1. 공개 PyPI v0.1.0을 새 임시 pipx 환경에 설치하고 실제 v0.1.0 setup으로 작업 폴더와 등록을 생성했다.
2. 같은 pipx 환경을 위 v0.2.0 wheel로 업그레이드했다. 가상환경 활성화 없이 앱 4개를 실행했다.
3. v0.1.0 작업 폴더에 --in-place를 적용해 스킬을 이전했다. 원래 README·등록·구 INSTALLATION.json이 유지됐고 재적용은 변경 0개였다. 백업은 프로젝트 밖이었다.
4. 다른 MCP 서버가 있는 별도 기존 프로젝트에 새 외부 등록을 만들며 적용했다. 기존 README·서버·공유 쓰기 가능한 일반 .gitignore를 보존했고, 생성 MCP는 pipx Python을 사용했다.
5. pip check와 설치본의 실제 setup·스킬·STDIO MCP 11개 스키마/프로필·훅 3개를 확인했다. 등록 대상 0개·장치 검사 0회·모델 0턴·신뢰 자동 부여 없음이다.

사용자 전역 pipx·셸 설정·운영 등록·기존 진단 저장소를 변경하지 않았다. 새 후보를 PyPI나 GitHub Release로 업로드하지 않았다.

## 남은 인수

사용자의 전체 진행 요청으로 커밋·푸시와 새 배포 준비까지 진행한다. 기존 Trusted Publisher와 같은 워크플로/환경을 사용하도록 v0.2.0 게시 경로를 준비했으나 Release/매니페스트·게시 실행은 아직 만들지 않았다. 현재 등록은 충돌 배제 false·격리 없음이다. 스킬의 운영 경계에 따라 AI가 이를 승인으로 바꾸거나 TTY에 승인 입력을 대신하지 않으며, 운영자의 현재 선언과 구체적인 계획 확인을 기다린다. 이 점검은 로컬 등록/기존 상태의 읽기 전용 조회이며 Pi에 접속하지 않았다.

- 현재 실제 주소·충돌 배제와 구체적인 계획 승인 후 Pi의 정상 활성/절전·샘플·복원 결과를 확인한다.
- 새 변경 절차의 취소/복원 불확실성·메모리를 실제 환경에서 별도로 평가한다. v0.1.0의 64MiB 결과를 새 기능 보장으로 재사용하지 않는다.
- 새 스킬 흐름의 실제 모델 행동과 승인 대기/재개를 별도 범위 승인 후 평가한다.
- Python 3.11·다른 OS·다른 pipx/uv 백엔드는 이번 실행 검증에 포함하지 않는다.
- 검토 후 커밋·릴리스 소스·후보 아티팩트를 결합하고 새 PyPI 배포를 진행한다. v0.1.0 파일/태그/매니페스트는 그대로 유지한다.
