# 남은 실물 오류 인수의 변경 계획

상태: **2026-11-25 사용자가 세 가지 변경 시험을 승인했다. 권한 거부·dummy 점유는 실물 관측과 복구까지 통과했다. 컨트롤러 비활성도 준비 경로 수정 후 실제 관측·복구까지 통과했다. 세 가지 승인 시험을 모두 완료했다.** 일반 진단은 계속 읽기 전용이다. 이 문서는 운영 MCP에 변경 도구나 sudo 권한을 추가하지 않는다. 오류 유도는 운영자가 감독하는 별도 시험 준비 작업이며 실제 검사는 기존 MCP로 수행한다.

## 공통 범위

- 기존 Pi·대상 ID·버스 1·공유 증거 저장소를 유지한다. 다른 I2C 프로그램은 시험 직전에 모두 중지한다.
- 한 번에 한 조건만 바꾸며 변경 전 상태와 복구 방법을 기록한다. 각 변경은 60초 lease와 알람으로 제한하고, 복구 수단이 준비된 경우에만 시작한다. SIGKILL·전원 상실·커널에서 멈춘 I/O는 Python 정리 절차가 보장되지 않으므로 운영자 복구가 필요하다. 이를 복구 성공으로 기록하지 않는다.
- root가 필요한 준비는 사용자의 Pi 터미널에서 수행한다. 비밀번호를 채팅·설정·MCP 인자에 넣지 않는다. sudoers 변경·패키지 설치·부트 설정 편집·자동 재부팅은 포함하지 않는다.
- 준비 또는 복구 조건이 충족되지 않으면 그 시험을 생략한다. 잠금·기존 드라이버·권한을 임의로 우회하지 않는다.
- 오류 상태에서는 보드·환경을 조사하고 센서 전송은 생략해 partial 보고서를 확정한다. 모델이 읽기를 생략하는 것과 코어가 강제 차단하는 것은 별도로 기록한다.
- 복구 후 센서 전송 없는 환경 조회로 원래 상태를 확인한다. 복구 실패나 원격 완료 불명확이면 추가 진단을 중단한다. 격리를 자동 해제하지 않는다.

## 1. 실제 접근 권한 거부

대상은 `/dev/i2c-1` 하나다. 변경 전 문자 장치 여부, inode·장치 번호·소유자·그룹·모드·POSIX ACL을 확보한다. ACL 백업이나 복원이 불가능하면 시험하지 않는다.

준비 작업은 원래 메타데이터를 별도 보존한 뒤 이 노드의 접근 권한을 일시적으로 제거하는 것이다. 소유자·그룹은 바꾸지 않는다. 시험 기대값은 비특권 진단 계정의 access_allowed=false이며 센서 읽기를 시도하지 않는 것이다.

복구는 처음 보존한 모드와 ACL을 정확히 되돌리는 것이다. 흔히 쓰는 0660 등으로 추정 복원하지 않는다. 노드가 재생성됐거나 메타데이터가 다른 작업에 의해 바뀌면 자동 복원을 중단하고 운영자에게 알린다. 이 시험은 해당 시간 동안 다른 I2C 사용자에게도 영향을 줄 수 있다.

## 2. 실제 커널 드라이버 점유

범위는 버스 1의 주소 0x68 하나다. `/sys/bus/i2c/devices/1-0068`이 이미 존재하면 생성·삭제하지 않고 중단한다. 사용자가 0x69로 물리 배선을 바꾼 경우 이 계획을 그대로 적용하지 않는다.

기존 커널의 dummy 드라이버가 준비됐는지 확인한 뒤, `i2c-1/new_device`에 `dummy 0x68`을 등록해 주소를 예약한다. 실제 MPU6050 드라이버는 센서를 초기화할 수 있으므로 이 시험에 사용하지 않는다. 커널 드라이버 생성은 단순한 파일 관측과 달리 시스템 변경이다.

기대값은 driver_bound["104"]=true이고 센서 읽기 생략이다. 복구는 **이번 시험에서 생성한 장치임이 확인된 경우에만** `i2c-1/delete_device`로 0x68을 삭제한다. 기존 장치나 다른 작업자가 생성한 항목을 삭제하지 않는다. dummy 준비 과정에 모듈 설치나 다른 주소 탐색이 필요하면 중단한다.

## 3. 실제 어댑터 비활성

현재 존재하는 /sys/class/i2c-dev/i2c-1/device에서 어댑터를 찾고 그 상위 platform 컨트롤러와 bind/unbind 경로를 읽기 전용으로 확인하고, 정확히 같은 컨트롤러로 복구할 수 있는지 먼저 검증한다. 경로·장치 이름을 하드코딩해 다른 컨트롤러를 건드리지 않는다.

현재 컨트롤러를 일시 unbind해 어댑터를 없앤 뒤 MCP가 adapter_present=false를 보고하는지 확인한다. 복구는 같은 드라이버의 bind로 원래 컨트롤러를 되돌리고 버스·접근 조건을 다시 조사하는 것이다. 부트 설정은 편집하지 않는다. 이 작업은 버스 1에 연결된 모든 장치의 접근을 일시 중단하므로, 다른 사용자가 있거나 복구가 불명확하면 수행하지 않는다.

이미 수행한 **등록 버스 255의 실제 어댑터 부재 조회**는 이 시험의 대체 통과가 아니다. 그것은 없는 어댑터를 잘못 등록한 상황만 확인했다.

## 취소·메모리의 남은 범위

원격 검사 전 취소와 정상 passive 검사기의 종료는 확인했다. 실행 중 취소는 마지막에 별도 계획으로 수행한다. 실제 원격 작업을 끊으면 완료가 불명확해 영속 격리가 발생할 수 있다. 이 문서의 승인을 격리 해제 승인으로 재사용하지 않는다.

현재 /proc 관측은 샘플링이다. 관측값이 64MiB 이내여도 순간 peak와 모든 단기 자식을 포착했다고 주장하지 않는다. 샘플링을 전체 추가 peak RSS의 통과로 바꾸지 않는다. 엄격한 peak 인수에는 수집 범위를 확정한 추가 계측이 필요하다.

## 승인된 실행 도구

[대화형 실행기](../scripts/run_fault_acceptance.py)는 반드시 본인 터미널과 --confirm-changes·--confirm-exclusive-i2c가 필요하다. [관리자 준비 가드](../evals/diagnose-mpu6050/fault_guard.py)는 sudo가 확인한 UID, 고정 버스·주소·드라이버만 허용한다. 사용자 비밀번호 입출력은 터미널에 직접 연결하며 파이썬에서 수집하지 않는다. 관리자 변경 전에 실제 MCP 기준 관측과 동일한 부트 ID·어댑터 지문인지 다시 확인해 연결 대상이 바뀌면 거부한다.

가드는 /run에 소유자 전용 복구 메타데이터를, /run/user/<uid>에 해당 실행의 상태·해제 파일을 만든다. 정상 복구 후 복구·상태·해제 파일을 정리한다. root 전용 협력 잠금 파일 /run/lock/embedsleuth-fault-acceptance.lock은 안전한 재사용을 위해 유지하며 재부팅 때 사라지는 운영 메타데이터다. 복구 실패 시 원본 메타데이터를 보존하고 이후 시험을 중단한다.

각 사례는 정상 passive 기준 → 준비된 오류의 passive 관측 → 원상복구 → passive 재확인으로 실행한다. 센서 전송은 모두 0회다. 이 명령은 실행 중 취소·64MiB 엄격 peak·0x69의 검증을 포함하지 않는다.

```bash
.venv/bin/python -I scripts/run_fault_acceptance.py \
  --config /ABSOLUTE/PATH/targets.json --target lab-pi \
  --case all --confirm-changes --confirm-exclusive-i2c \
  --output /ABSOLUTE/PATH/fault-acceptance.json
```

기존 결과 파일은 덮어쓰지 않는다. 준비 불가·잘못된 기준 상태·복구 확인 실패 시 뒤 사례를 자동 실행하지 않는다. 문제가 나면 반복 실행하기 전에 출력과 보존한 복구 파일을 검토한다.
