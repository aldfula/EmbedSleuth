## 공개키 재등록 뒤 인증 재확인

사용자가 재등록 완료를 알린 뒤 새 passive 실행으로 한 번 확인했다. inspect_target은 1,418ms 뒤 authentication_failed였고, 추가 하드웨어 검사 없이 규칙 평가·partial 보고서로 마쳤다. 인증 절차만 비교한 OpenSSH도 동일한 계정·전용 키·엄격한 호스트 키 검증에서 서버의 공개키 거절을 확인했다. 원격 비교 명령은 true였으며 센서·환경 검사를 대체하지 않았다.

이 PC의 공개키와 개인키는 서로 일치하고 개인키 파일 권한은 0600이며 읽을 수 있다. 따라서 당시 재등록 미실행을 원인으로 단정하지 않았다. 사용자가 공유한 명령에는 호스트명 오타가 있었고 완료 메시지도 없었다. 이후 올바른 대상에 Number of key(s) added: 1을 확인한 뒤 실제 MCP 접속이 성공했다. 서버 권한·인증 정책 문제였다고 추정하지 않는다. 에이전트가 서버 설정이나 키 등록을 자동 변경하지 않았다.

## 인증 복구 후 실물 passive — 2026-11-25 19:51 KST

## 추가 취소·프로세스·어댑터 인수

- 기존 호스트의 직접 MCP로 새 passive 실행을 만들고 원격 검사를 시작하기 전에 취소했다. run-d15988b44a774d938f080c17ed786b19는 interrupted·증거 0개이며 재조회와 저장소의 cancelled·pending_operation=null을 확인했다. 실제 원격 동작 중 취소를 검증한 것은 아니다.
- [프로세스 관측기](../scripts/run_process_acceptance.py)는 별도 SSH 세션에서 /proc stat만 읽고, 실제 운영 MCP로 passive 검사를 수행했다. 15,035ms 동안 296개 표본, 최대 간격 67.098ms, 읽기 불가 PID 0개, 관측한 양의 RSS 증가 최대 31,812KiB(약 31.1MiB)였다. 요청 간격 20ms를 실제 측정 간격이라고 표시하지 않는다.
- 계측용 SSH 세션과 관측기 자체는 baseline으로 제외했다. 나머지 새 프로세스와 기존 프로세스의 RSS 증가를 합하므로 진단 SSH와 다른 작업의 증가·공유 페이지가 함께 잡힐 수 있다. 반대로 짧은 peak·프로세스를 놓칠 수 있어 전체 추가 peak RSS 판정은 unknown이다. [Linux proc 문서](https://docs.kernel.org/filesystems/proc.html)
- run-7b9c41effc014d4fb691e484e74e2ea3의 두 검사기 PID와 시작 tick이 마지막 표본에 없음을 확인했다. 원래 프로세스와 PID 재사용을 구분했다. 관측되지 않은 모든 자식의 종료까지 보장하지 않는다. 보고서는 partial, pending_operation=null이며 관측기는 종료 코드 0으로 끝났다.
- run-36cdbe7b076f4eadb2ebaa0c06f94f63은 예상 어댑터 255가 실제로 없음을 조사했다. 로컬 등록 변경은 실행 전후에만 했고 같은 대상·공유 저장소를 유지했다. Pi의 버스 1은 변경하지 않았다. 이 항목을 실제 컨트롤러 비활성의 통과로 계산하지 않는다.

종료 훅의 실제 오류 경로에서 PostToolUse 누락을 관측했다. 모든 관련 실행·원격 감사가 닫혔다면 누락 영수증을 그대로 남기고 경고만 반환하도록 수정했다. 미완료 실행·pending 작업·명시적 결과 검증 오류는 계속 한 번 보완한다. 원격 검사를 반복하거나 완료 영수증을 꾸며내지 않는다. 이 수정의 3개 회귀를 포함한 훅·프로세스·관리자 준비 가드 시험은 외부 모델 없이 수행했다.

사용자가 본인 터미널에서 승인된 대화형 실행기를 실행했다. PC 결과 파일과 영속 보고서를 대조했다.

| 사례 | 오류 관측 | 복구 관측 | 판정 |

## 계측 구현과 해석

원격 표준 라이브러리 검사기에 Linux getrusage 관측을 추가했다. probe peak RSS, 기다려 종료한 단일 자식의 peak RSS, 둘을 더한 보수적 상한, 실행·CPU 시간, PID·프로세스 시작 tick을 기록한다. 계측이 불가능하면 available=false이며, 관측·정책·실행 상태를 바꾸지 않는다. Pi에 패키지를 설치하거나 기록 파일을 만들지 않는다.

Linux의 ru_maxrss 단위는 KiB이고 RUSAGE_CHILDREN은 전체 트리 합계가 아닌 종료한 자식 중 가장 큰 값이다. 이 검사기는 전송 자식을 한 개만 실행한다. 따라서 두 peak의 합을 동시 실측 peak라고 부르지 않고 보수적 상한으로 보고한다. SSH 데몬·실행 셸·다른 시스템 프로세스는 이 계측에서 제외한다. **이 부분합이 64MiB 이하라도 시스템 전체 추가 RSS 목표가 검증된 것은 아니다.** 전체 추가 RSS는 별도 계측 인수 항목으로 남긴다. [Linux getrusage 명세](https://www.man7.org/linux/man-pages/man2/getrusage.2.html)

각 원격 호출은 순차 실행되므로 여러 호출의 peak를 다시 합하지 않는다. 인수 요약은 유효한 샘플의 최대 상한을 사용하고, 하나라도 64MiB를 넘으면 fail, 누락·잘못된 샘플이 있으면 unknown으로 남긴다. 시간은 코어의 도구당 10초와 감독 종료 정리 0.2초를 구분한다. 보고서 partial/interrupted·실행 오류·식별 불일치를 서로 대체하지 않는다.
