# Phase 2 교차 검토

검토일: 2026-11-18. 사용자 요청에 따라 세 에이전트가 자신의 주 구현 영역을 바꿔 독립 검토하고, 주 에이전트가 수정과 전체 검증을 통합했다. 실물 SSH·Pi 접속은 수행하지 않았다.

## 검토 범위

| 담당 관점 | 검토 범위 |
|---|---|
| 계약·정책 검토자 | 저장소 내구성, 다른 실행·프로세스 중단, 중복·복구·잠금·보고서 |
| 저장소 구현자 | SSH 대상·키·인자 경계, 원격 검사, 감독·자식 프로세스 수명 |
| SSH 구현자 | 코어 입력·상태·신선도·예산·식별 증거·완료 판정, 사용 문서 |

기존 전체 354개 시험을 다시 실행해 통과한 뒤, 기존 시험에서 빠진 반례를 추가했다. 발견한 결함은 재현 시험이 수정 전에 실패하고 수정 후 통과하는 것을 확인했다.

## 발견과 수정

| 우선순위 | 발견 | 수정·회귀 검증 |
|---|---|---|
| P1 | 서버 B가 시작 당시 실행 중인 A를 건너뛴 뒤 살아남으면 A의 후속 중단을 놓침 | 대상 잠금 아래 모든 동일 대상 실행을 복구한 뒤 새 작업 허용; 살아남은 저장소 반례 차단 |
| P1 | 호스트가 KeyboardInterrupt를 잡고 계속하면 다른 실행이 불확실한 읽기를 반복할 수 있음 | 인터럽트는 다시 전달하되 먼저 대상 격리·상태 저장; 새 실행에서 추가 전송 없음 |
| P2 | 같은 SSH 접속점을 다른 ID로 등록하면 잠금·격리를 분리할 수 있음 | 정규화 호스트·포트 중복 거부; 계정·버스 변경 별칭도 차단 |
| P2 | 이전 부트·어댑터의 식별 성공으로 현재 환경을 complete로 표시 | 대상 재조사에서 부트·키·보드 변경 시 실행 차단, 실패한 갱신에도 원래 결합 보존; 현재 환경과 일치하는 식별 증거만 완료 범위에 사용 |
| P2 | 의도 기록의 fsync 지연 후 예산·신선도가 만료돼도 전송 시작 | 영속 기록 후 도구·활성·TTL 잔여 시간과 환경 신선도 재검사; 원격 미실행 상태로 의도 종료 |

추가로 사용자 지정 짧은 TTL도 원격 기한에 반영하고, 기록 저장 중 TTL이 끝난 경우 interrupted 보고서를 유지하도록 검증했다. 과거 증거·원래 수집 시각·완료 캐시는 보존하며 현재 환경의 새 관측으로 가장하지 않는다.

## 추가 시험

- [코어 재검토 시험](../tests/test_review_core.py): 부트·어댑터 변경, 실패한 갱신, 환경 없는 재조사, 기록 지연 후 예산·신선도·TTL, 짧은 TTL 기한.
- [저장소 재검토 시험](../tests/test_review_storage.py): 살아남은 서버의 복구, 잡힌 호스트 인터럽트, 동일 접속점 별칭·정규화, 별도 접속점.
- [전송 재검토 시험](../tests/test_review_transport.py): SIGTERM을 무시하는 작업자 강제 종료, 실제 로컬 자식 프로세스 그룹 정리, 최신 드라이버 점유·누락 지문에서 전송 차단.
- 기존 저장소 시험에 recover_target의 대상별 복구·바쁜 실행·잘못된 상태 차단을 추가했다.

최종 전체 시험 수·실행 시간과 패키지 검증 결과는 [구현 계획](implementation-plan.md#phase-2-검증)에 기록한다. 수정본 재검토에서 현재 Phase 2 범위의 추가 차단 결함은 발견하지 못했다.

## 운영 경계와 미검증 범위

한 물리 장치에는 안정적인 대상 ID와 하나의 공유 저장소를 사용한다. 다른 DNS/IP 별칭·SSH 터널·서로 다른 저장소가 같은 장치인지 자동 판별하지 않는다. ID나 저장소를 바꿔 격리를 우회해서는 안 된다. 현재 전체 실행 순회 복구는 기록 수에 비례하므로 장기 운영의 성능·보존 정책이 필요하다.

실제 Pi 3의 OS·32/64비트 ioctl, sshd와 커널 I/O 수명, 추가 peak RSS 64MiB 목표, 타 프로그램과의 실제 I2C 충돌은 Phase 6 실물 인수 범위다. 스킬·훅·MCP 연결은 Phase 3–5 범위다. 이번 판단은 오프라인 코어 구현을 커밋하는 조건을 충족했다는 뜻이며 MVP 전체나 실물 안전성 인증이 아니다.
