# v0.2.0 사용과 검증 범위

개발 중인 0.2.0 후보의 안내다. 현재 공개 PyPI는 0.1.0이며 `pipx upgrade embedsleuth`만으로 아래 기능이 설치되지는 않는다. 검토한 0.2.0 wheel을 별도 환경에서 시험한 뒤 정식 게시한다. Linux/Python 3.12가 이번 실행 검증 환경이다.

## 기존 프로젝트에 연결 자료 추가

기존 등록 파일을 재사용하는 경우, 작업할 프로젝트에서 실행한다. --directory를 생략하면 현재 폴더를 사용한다.

```bash
embedsleuth-setup --in-place --config /ABSOLUTE/PATH/targets.json --dry-run
embedsleuth-setup --in-place --config /ABSOLUTE/PATH/targets.json
```

처음 설치하는 PC라면 사용하지 않은 외부 등록·증거 경로를 지정한다.

```bash
embedsleuth-setup --in-place \
  --config "$HOME/.config/embedsleuth/targets.json" \
  --init-config --state-directory "$HOME/.embedsleuth-state"
```

새 등록은 대상 0개로 시작한다. 이미 등록·증거가 있으면 --init-config와 --state-directory를 생략하고 원래 등록을 재사용한다. setup은 Pi 접속·등록 변경·증거 복구·격리 해제·호스트 신뢰 부여를 수행하지 않는다.

기존 README·소스·다른 MCP 서버와 훅을 보존한다. TOML에 EmbedSleuth 테이블을 추가하고 훅 JSON의 다른 키/이벤트를 보존한다. `.gitignore`에는 생성된 로컬 파일의 제외 규칙을 추가한다. JSON의 들여쓰기는 재직렬화될 수 있다. 충돌·잘못된 형식·중복 JSON 키·링크·공유 쓰기가 가능한 호스트 설정 파일은 중단 조건이다. 같은 설정으로 반복 적용해도 훅을 복제하지 않는다. TOML inline table처럼 안전하게 테이블을 덧붙일 수 없는 구조는 수동 병합을 요구한다.

기존 설정 백업은 등록 파일 부모의 소유자 전용 `.embedsleuth-setup-backups` 아래에 둔다. 프로젝트 안에 비밀이 있을 수 있는 백업을 복제하지 않는다. 프로젝트의 `.embedsleuth/installation.json`은 설치 버전과 관리 스킬 해시를 기록한다. `.embedsleuth/pending.json`이 남았으면 중단된 적용이므로 새 적용을 멈추고 표시된 백업과 파일 해시를 검토한다. 프로세스 종료를 포함한 파일 여러 개의 변경을 하나의 원자적 트랜잭션으로 보장하지 않는다. 실행 중 외부 편집을 피한다.

v0.1.0 생성기의 INSTALLATION.json이 원래 등록/상태/Python과 일치하면 공개 v0.1.0 wheel에서 확인한 정확한 원본 스킬 해시만 업그레이드한다. 수정한 스킬이나 다른 MCP 실행 경로는 강제로 덮어쓰지 않는다. 구 설치를 다른 Python 경로로 옮긴 경우 설정을 검토해 병합한다. 호스트의 기존 MCP를 종료·재연결하고 바뀐 스킬과 훅을 검토한다.

## 센서 데이터 점검

자연어로 `$diagnose-mpu6050로 등록된 lab-pi의 가속도·자이로·온도를 짧게 점검해 줘`처럼 명시적으로 요청한다. 현재 예상 주소와 다른 I2C 사용자 중지를 먼저 확인하고 로컬 충돌 배제 선언도 준비한다. 기본 read_only/passive는 설정을 변경하지 않는다.

sensor_check 실행은 같은 환경 조사와 WHO_AM_I 일치를 거친 뒤 `prepare_sensor_sampling`으로 계획을 만든다. 이 도구 자체는 원격 통신을 하지 않는다. 계획에는 대상·run·부트·SSH 지문·어댑터·주소·등록 digest·정책·고정 절차·만료가 들어간다. 승인 전후 대기 시간도 원래 120초 활성 예산과 30초 환경 신선도에 포함된다. 계획 자체의 최대 유효 기간도 120초다.

계획 생성 후 상태는 sampling_planned다. 원격 의도와 감사가 모두 닫히고 보고서가 partial이면 Stop 훅은 사용자 승인을 기다리는 턴 종료를 허용한다. 이 예외는 승인이나 기한 연장이 아니다. 미확인 원격 작업에는 적용하지 않는다. 다음 턴에서 승인과 신선도·예산을 다시 검사하고, 수집 후에는 sampled 상태에서 보고서를 마무리한다.

운영자가 자신의 터미널에서 실제 값으로 실행한다.

```bash
embedsleuth-approve-sampling \
  --config /ABSOLUTE/PATH/targets.json \
  --run-id ACTUAL_RUN_ID --plan-id ACTUAL_PLAN_ID
```

계획 내용을 확인한 뒤 화면에서 요구하는 `approve ACTUAL_PLAN_ID`를 직접 입력한다. 파이프 입력과 자동 승인 옵션은 제공하지 않는다. 이 명령은 로컬 승인 기록만 쓰며 Pi에 접속하지 않는다. AI는 승인 입력·직접 함수 호출·상태 파일 편집으로 이를 대신하지 않는다. 같은 사용자 권한의 악성 코드로부터 파일 시스템 전체를 보호하는 보안 경계는 아니며, MCP/스킬 안에서 AI가 승인을 만들어내지 못하게 분리한 운영 경계다.

승인 후 환경 신선도를 필요에 따라 갱신하고 `sample_sensor_data(run_id, plan_id, operation_id)`를 호출한다. 승인과 동일한 부트·등록·어댑터·주소·프로필·정책이어야 한다. 승인 소비를 전송 전에 영속화하고, 같은 operation_id의 완료 결과는 원래 시각으로 재사용한다. 다른 operation_id로 같은 계획을 다시 실행하지 않는다.

허용 절차는 고정돼 있다.

1. WHO_AM_I와 전원·범위·제어 설정을 읽는다. self-test, 축 standby, 외부/정지 클록, cycle, 온도 비활성, 인터럽트, FIFO/DMP/보조 제어 등 비지원 상태는 초기화하지 않고 중단한다.
2. 절전 상태이면 PWR_MGMT_1(0x6B)의 SLEEP 비트만 해제하고 확인한다. 이미 활성 상태이면 설정을 쓰지 않는다.
3. 0x3B부터 14바이트 burst를 5회 읽는다. 100ms 기동 대기와 최소 50ms 호출 간격은 진단 절차의 선택값이며 정밀 샘플 주기나 모든 설정의 안정화를 보장하지 않는다.
4. 관측한 범위를 이용해 signed 16-bit 원시값을 g·°/s·칩 내부 °C로 변환한다. 범위나 필터를 변경하지 않는다.
5. 변경했으면 관련 설정·부트·어댑터를 재확인한 뒤 원래 0x6B 값을 복원하고 읽어 확인한다. 다른 설정이 바뀌었으면 오래된 값으로 덮어쓰지 않는다.

샘플링에는 전체 9초 이상의 남은 전송 예산을 요구하고, 원격 작업/복원에는 별도 짧은 기한을 둔다. 전송 timeout이나 미확인 I/O 뒤에는 복원이라는 이유로 새 I2C 전송을 시작하지 않는다. 복원 미확인·강제 종료·전원/통신 단절은 영속 격리 대상이다. 모든 종료에서 복원을 보장하지 않는다. 수신한 증거로 복원을 확인할 수 없으면 보고서에서 미확인으로 남긴다. 자동 재시도·일반 격리 해제는 제공하지 않는다.

## 결과 해석

개발 저장소의 실물 인수는 운영자 본인 터미널에서 다음 형태로 실행할 수 있다. 기존 비공개 등록과 증거 저장소를 그대로 사용하고 새로운 생산 STDIO MCP에 연결한다. 운영자가 다른 I2C 프로그램을 중지한 뒤 기존 등록의 해당 대상에 `conflicting_use_excluded=true`를 직접 설정한 상태여야 한다. 명령의 현재 확인은 false인 등록을 덮어쓰지 않는다. 실제 주소·다른 I2C 작업 중지를 먼저 `ready`로 확인하고, 이어 표시되는 구체적인 센서 계획을 승인 명령의 안내대로 직접 입력한다. AI가 승인 입력을 대신하지 않는다. 120초 예산 안에 완료하지 못하면 partial 보고서로 마치며 자동 재시도하지 않는다. 종료 후 해당 선언을 false로 되돌려 다음 검사에 자동 재사용하지 않는다.

```bash
.venv/bin/python scripts/run_sampling_acceptance.py \
  --config /ABSOLUTE/PATH/targets.json --target REGISTERED_TARGET_ID --address 0x68
```

이 인수는 실제 MCP·승인 명령·센서 수집·복원을 확인한다. AI 모델의 스킬 선택이나 전체 SSH 세션 메모리 측정은 포함하지 않는다. 실행 실패 시 기존 보고서를 검토하며 센서를 반복해서 읽어 종료를 증명하지 않는다.

획득 성공은 센서 전체 정상·정품·보정 정확도 확인이 아니다. 여러 snapshot은 같은 센서 업데이트를 다시 읽을 수 있다. 동일값은 정지 상태나 느린 출력 속도에서도 나타나며, 포화·온도 범위 경고도 고장 확정이 아니다. 온도는 주변 온도가 아니다. raw bytes·관측 설정·변환 결과·wakeup_attempted·restoration_confirmed와 원래 증거를 함께 보존한다. sensor_check 보고서는 식별만 통과했을 때 complete가 되지 않는다.

기존 0.1.0 실물 인수는 그대로 보존한다. 새 기능의 코드/가짜 장치/패키지 검증과 실제 Pi의 깨우기·측정·복원·메모리·모델 행동 검증을 구분한다. 실제 Pi 검증 전 현재 주소·충돌 배제·구체적 변경 계획의 승인을 새로 확인한다.

완료한 자동 회귀와 실제 pipx 업그레이드 범위는 [로컬 후보 검증 기록](v0.2.0-verification.md)을 따른다.
