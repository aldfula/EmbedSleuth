# MVP 메모리 인수 기준 결정

상태: 2026-11-26 사용자의 순차 인수 진행 요청에 따라 적용.

## 결정

MVP의 메모리 인수 기준은 **Pi의 진단 관련 SSH 서비스와 로그인 세션을 포함하는 커널 과금 메모리 최대값 상한 64MiB 이하**로 한다. 관측한 검사기·sshd의 cgroup 소속, 같은 부트·그룹 inode, 카운터 가용성과 단조성을 확인해야 한다. 현재 검증한 Linux 구성의 집계 범위는 ssh.service와 user.slice다.

각 그룹의 생성 이후 memory.peak를 합한다. 계측기 자체와 기존 로그인·다른 작업도 포함하는 보수적 상한이며, 서로 다른 시점의 peak 차감으로 진단 증가분을 만들지 않는다. 그룹을 이동하거나 카운터를 초기화하지 않는다.

상한이 64MiB 이하이고 범위가 확인되면 pass다. 계측 불가·소속 누락·그룹 변경·부트 변경은 unknown이다. 넓은 집계 범위의 상한이 예산을 넘으면 진단 자체의 예산 초과로 단정하지 않고 unknown으로 두어 별도 분리 계측을 요구한다.

## 이유와 적용 범위

목표는 Pi에서 LLM·에이전트 프레임워크 없이 작은 검사기를 실행할 수 있는지 검증하는 것이다. 실제 커널의 최대값 기록은 /proc 표본 사이의 짧은 peak를 놓치는 문제를 피하고 SSH·셸을 제외한 검사기 부분 RSS보다 넓은 범위를 검증한다. 다만 과금 메모리와 RSS는 공유 페이지·캐시·커널 메모리의 집계 방식이 다르므로 동의어로 쓰지 않는다.

기존 ‘전체 추가 peak RSS 합계 64MiB’는 MVP 필수 릴리스 기준에서 제외하고 참고·향후 계측 항목으로 남긴다. 미측정을 통과로 바꾸지 않는다. getrusage의 검사기+회수한 단일 자식 RSS 부분 상한 역시 참고 지표다. 이 결정은 OS별 지원 범위·시간 제한·읽기 정책·관측 프로세스 종료 보장을 확대하지 않는다.

## 기존 실측에 대한 판정

- 현재 검증 구성: Pi 3 Model B Rev 1.2, Debian 12, aarch64, kernel 6.12.115+rpt-rpi-v8, Python 3.11.2.
- passive 상한 39,522,304바이트(37.69MiB), 0x68 식별 포함 상한 39,813,120바이트(37.97MiB): **새 MVP 기준 pass**.
- 엄격한 전체 추가 RSS는 여전히 미측정이며 참고 항목이다. 다른 OS·작업 부하의 예산을 자동 보장하지 않는다.
