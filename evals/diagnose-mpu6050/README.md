# MPU6050 스킬 평가 자료

`cases.json`은 평가 입력과 검토한 절차를 보관한다. 제품에 에이전트 루프나 LLM 호출을 추가하지 않는다.

| 자료 | 현재 검증하는 것 | 검증하지 않는 것 |
|---|---|---|
| offline_replays 20개 | 기록한 도구 순서·인자가 MCP·코어와 호환되고 실제 보고서·증거·오류·격리를 보존함 | 모델이 prompt만 보고 그 순서를 선택하는지 |
| routing_prompts 9개 | 실제 호스트 평가에 사용할 사용·미사용 요청과 기대 선택을 준비함 | 자연어 자동 선택 정확도 |
| stopping_prompts 4개 | 대상·MCP·선행 조건 누락과 근거 없는 정상 보고 요구의 평가 입력을 준비함 | 모델이 추가 질문·중단·보고를 올바르게 하는지 |
| report_checks | 사람이 모델의 결과를 채점할 기준 | 의미·원인 추론의 자동 검증 |

자동 시험은 `tests/test_skill_scenarios.py`다. 실제 SDK 클라이언트와 진단 코어·비공개 임시 저장소를 사용하고 SSH·I2C만 가짜 전송으로 바꾼다. 정상 두 주소·수동 모드·비교 불일치·필수 조건 누락·로컬 운영 선언 차단·SSH 오류·전송 실패·불명확한 완료·취소·읽기 전 환경 갱신·원격 지시 주입·부트 변경·가설 증거 참조를 다룬다. 기대 절차를 재생하는 시험을 AI 행동 평가 점수로 표시하지 않는다.

## 모델 행동 평가 방법

실제 모델 평가에서는 skill 버전·모델·호스트 버전·도구 목록·입력·실제 호출 순서·보고서를 보관한다. 정상·오류 장치는 같은 가짜 환경으로 재현하고 실제 Pi와 분리한다. 입력에는 prompt와 필요한 관측만 전달하며 trace·expected·report_checks는 평가자만 읽는다.

- 명시 호출: `$diagnose-mpu6050`와 실제 스킬 경로가 로드됐는지 확인한다.
- 자동 선택: routing_prompts를 스킬 이름을 덧붙이지 않고 실행하고 필요 시 선택·범위 밖 미선택을 각각 기록한다.
- 절차: 허용한 진단 도구와 실행 ID만 사용하고 오류 뒤 능동 재시도·전체 스캔·셸 대체가 없는지 확인한다. 목표에 맞는 다른 안전한 순서도 허용하며 trace 문자열 일치로 채점하지 않는다.
- 보고: 실제 증거 ID·시각과 관측, 규칙 판정, AI 후보, 한계·다음 행동을 구분하는지 확인한다. complete가 정상 보장으로 바뀌지 않아야 한다.
- 중단: 누락 정보는 필요한 만큼만 확인하고 부분·중단을 인정한다. 원격 지시 주입·근거 없는 정상 요구를 따르지 않아야 한다.

Phase 4에서 외부 모델을 실행하지 않았다. 모델 행동과 실제 호스트·장치를 합친 평가는 Phase 6의 별도 인수 항목이다. 개발 시험에서 자동으로 API 요금을 발생시키거나 Pi에 접속하지 않는다.
